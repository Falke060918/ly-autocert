# learn — 학습 수신함 확정 반영

수신함(`docs/learn/`, 로컬 전용)의 후보를 검토해 **사람 승인을 거쳐서만** 기억
파일(GOTCHAS·rules)과 스킬로 반영한다. 후보는 `scripts/learn-harvest.sh`(세션
종료 회수)·넛지·auto memory가 쌓는다 — 학습은 자동, **확정은 항상 수동**이다.

## 0. 수신함 확인

- `docs/learn/`의 `.gitignore` 외 파일을 전부 읽는다. 비어 있으면 "후보 없음" 한 줄 보고하고 끝낸다.
- 같은 내용의 후보가 여러 파일에 반복되면 하나로 합치되, **반복 횟수를 세어 둔다**
  (2단계 승격 판정과 ECC 승격 사다리의 "반복 확인" 판정에 쓴다).

## 1. mem0식 모순 검사 (후보별)

각 후보를 기존 기억 — `docs/GOTCHAS.md`, `.claude/rules/`, (있으면) `CLAUDE.md`의
관련 규칙 — 과 대조해 셋 중 하나로 판정한다. harvest가 붙인 판정은 초안일 뿐이며
여기서 반드시 재검한다:

| 판정 | 동작(승인 시) |
| --- | --- |
| 신규 | 겹치는 기존 항목 없음 — 해당 파일에 그대로 추가 |
| 갱신 | 기존 항목과 겹치되 새 사실이 더 정확 — 기존 항목을 덮어쓰고 확인일 갱신 |
| 무효화 | 기존 항목이 틀렸음이 확인됨 — 삭제 또는 "무효" 표시를 **제안** |

- 충돌 판정(갱신·무효화)은 어느 기존 항목과 충돌하는지 **원문을 인용해** 보여준다.
- 판단이 안 서면 추측으로 덮어쓰지 않는다 — 보류로 분류해 수신함에 남긴다.

## 2. Voyager식 스킬 승격

- 스킬 후보 중 **같은 절차가 2회 이상 성공**한 것만 승격 대상이다
  (수신함 반복 + 이번 세션 실측 합산). 1회짜리는 수신함에 남겨 다음 검토로 넘긴다.
- 승격 대상은 `.claude/skills/<이름>/SKILL.md` **초안**을 만든다:
  frontmatter(name·description) + 절차 단계 + 성공 사례 2건 요약.
- 함정과의 경계: 절차(무엇을 어떤 순서로)는 스킬로, 함정(무엇을 하면 데인다)은
  함정 계층으로 보낸다 — 어느 파일인지는 저장소에 따라 갈리므로 4단계의 분기를 따른다.
  함정 목록에 절차가 사는 것이 v1의 실측 결함이었다.

## 3. 사람 승인 관문 (필수 — 생략 불가)

**[3계층(멈춤선)]** 이 관문은 무인 모드(`/automode on`)에서도 유지된다 — 무인은 승인 관문을 대체하지 않는다. 계층 정의는 `.claude/agents/orchestrator.md`.

- 반영 전에 후보 전부를 AskUserQuestion으로 묶어(4개씩) 낸다. 항목마다
  `현재 판정 / 반영할 내용`을 적고, 선택지는 **반영 / 나중에 (보류) / 뺀다 (제외)**.
- **어떤 후보도 승인 없이 기억 파일·스킬에 쓰지 않는다.** 무효화(기존 항목 삭제)도
  같은 관문을 거친다 — 잘못 배운 규칙이 조용히 굳는 것이 잊는 것보다 위험하다.
- 사용자가 "전부 반영"처럼 일괄 지시하면 그 지시가 승인이다 — 재확인하지 않는다.

## 4. 반영과 정리

- 승인분만 반영한다: 규칙 후보 → `.claude/rules/`(조건부 로드 규칙) 또는 함정 계층,
  스킬 승격 → `.claude/skills/<이름>/`.
- **함정의 목적지는 저장소에 따라 갈린다.** `.claude/identity` 의 `identity:` 값을 읽는다 —
  파생 프로젝트(`project`)면 `docs/GOTCHAS.md` 가 그대로 목적지이고, 템플릿 원본(`template`)이면
  GOTCHAS 에 아무것도 넣지 않고 플랫폼 일반 함정을 `.claude/rules/shell-traps.md` 로 보낸다.
  분기의 단일 원본은 `.claude/rules/memory.md` 다(행동 문제와 템플릿 기계 자체의 함정은
  목적지가 또 다르다) — 여기서 규칙을 다시 적지 않으니 판단이 서지 않으면 그 파일을 읽는다.
- 처리 완료(반영·제외)한 후보는 수신함 파일에서 지운다. 파일이 비면 파일을 삭제한다.
  보류 후보만 남긴다. 수신함은 gitignore라 이 정리는 커밋에 안 잡힌다.
- 반영으로 바뀐 파일만 커밋한다. 커밋 메시지에 반영/보류/제외 건수를 한 줄 남긴다.
