# Codex 실행 계약 — Claude 운영 방식의 런타임 보정

이 문서는 Codex에서 읽는 모든 역할·규약·스킬의 실행기 가정보다 우선한다.
행동 원칙은 보존하되 Claude의 도구 이름·권한·로그 형식을 Codex의 기능이라고 주장하지 않는다.

## 역할 경계와 시작

- 메인만 orchestrator다. 서브에이전트/위임받은 worker는 자기 역할로 직접 실행하며 main-only 시작·위임·사용자 승인 게이트를 재실행하지 않는다. 재위임하지 않고 막힌 사항을 부모에게 돌려준다.
- 메인은 사소한 수정, 파일 쓰기, 커밋, 셸 검증도 implementer에게 위임한다. explorer는 조사, planner는 설계, reviewer는 독립 검증을 맡는다. 순수 정보 답변에 필요한 짧은 파일 1–2개와 운영 지침 읽기만 메인이 직접 한다.
- Codex의 도구 제거 기능으로 이 경계를 강제했다고 주장하지 않는다. "메인에게 Bash/Write가 없다"라는 이식 원문의 표현은 **직접 실행하지 않는 행동 규약**으로 읽는다. read 도구가 셸뿐이면 운영 지침·짧은 파일을 읽는 셸 호출만 허용되며 검사·편집·Git 실행으로 넓히지 않는다.
- 서브에이전트 도구가 없거나 상위 정책으로 위임이 금지되면 직접 구현으로 대체하지 않는다. 가능한 읽기 확인까지만 하고 기능 한계와 필요한 사용자 선택을 보고한다. 다른 실행기로 우회하지 않는다.
- 역할 원본은 `.codex/roles/*.md`, worker 등록은 `.codex/agents/*.toml`이다. main의 전체 orchestrator는 `scripts/sync-orchestrator.py`가 config의 `developer_instructions`로 렌더한다. 신뢰된 프로젝트의 새 세션에서 자동 주입되며, 미주입이면 AGENTS의 필수 읽기 경로를 따른다. `model_instructions_file`로 기본 시스템 지침을 교체하지 않는다.
- 원문 전체를 읽지 않는 비용 규칙의 예외는 이 시작 지침이다. 본문이 이미 주입됐으면 같은 역할 파일을 다시 읽지 않는다.

## 도구 대응

- Agent/Task는 현재 제공된 서브에이전트 도구다. 존재하지 않는 `name`/unnamed/`run_in_background`/`isolation` 인자를 보내지 않는다. 현재 스키마의 필수 task_name 등을 사용하며 모델은 현재 설정을 상속한다. haiku/sonnet/opus와 effort는 Claude 측 설정·과거 관측이지 Codex 모델 이름이 아니다.
- 3자 검토는 서로 다른 세 입력을 보존한다. 새 order/user 검사관에게 부모 대화 전체를 fork하지 않는다(`fork_turns="none"` 등 지원되는 격리 기능 사용). 세 개를 모두 실행한 뒤 결과를 기다려 병렬로 진행한다. 슬롯이 부족하면 큐/차례 실행하고 시간상 제약을 알리되 세 판정을 한 사람의 세 역할로 대체하지 않는다.
- 병렬 커밋은 격리된 작업트리, 파일이 분리되고 Git 쓰기가 없는 작업은 공유 트리+커밋 금지로 한다. 자동 worktree 인자가 없으면 implementer가 승인 범위에서 명시적 작업트리를 준비하거나 순차로 진행한다. 시작 기준 커밋·브랜치·필수 파일을 실제로 확인하며 "항상 세션 시작 커밋"으로 단정하지 않는다. rebase/merge는 자신의 작업 브랜치에서만, 중단 시 복구하고 보고한다.
- Orca 환경에서는 해당 Orca 스킬과 `.codex/rules/orca.md`를 따른다. 연결 실패만으로 권한을 넓혀 샌드박스 밖 호출을 시도하지 않는다. 허용된 환경에서만 실측하며 확인 불가를 앱 꺼짐으로 판정하지 않는다.
- Read/Glob/Grep/Bash/Edit/Write는 실제 제공된 읽기·검색·셸·패치 도구에 대응한다. 편집은 apply_patch를 사용한다. 원문의 heredoc/printf 쓰기는 파일 형식 예시이지 강제 편집 방법이 아니다.
- explorer/reviewer의 읽기 전용은 제품 파일에 대한 규약이다. 지정된 조사·판정·임시 산출물은 쓸 수 있다. planner는 지정된 docs 계획과 자기 planner 판정만 쓰며 셸 실행·커밋은 implementer 몫이다. 어떠한 역할도 도구가 있다는 이유로 권한 범위를 넓히지 않는다.
- AskUserQuestion은 사용할 수 있는 질문 도구에 대응한다. 문항 수·선택지·모드 제한은 실제 스키마 우선(원문의 4문항 고정값은 나눠 보낸다). 도구가 없는 대화형 환경에서 중요한 미결정 사항은 짧은 일반 질문으로 묻는다. 헤드리스에서는 필요한 결정을 보고/확인 필요 표시로 남기고 해당 실행을 멈춘다.
- 이미 승인된 목적·범위·방식은 다시 묻지 않는다. 사용자의 "ask하지 마/바로 해"는 1계층 진행 확인 생략 요청으로 적용하고 위임장에 "이미 승인됨 — 확인 질문 없이 완료까지"를 적는다. 확인 생략은 범위 확장·새 비용·비가역 조작의 승인이 아니다.
- 스킬은 `$이름` 또는 해당 SKILL.md를 읽는 방식이다. 이식 본문의 `/kickoff` 등 슬래시 이름은 대응 스킬을 뜻하며 가짜 slash command를 호출하지 않는다. `/clear`·`/compact`는 호스트가 지원하는 세션 관리만 사용하며 대화를 자동 폐기하지 않는다.

## 권한·수명·로그

- 상위 시스템·개발자 지침과 실제 권한 정책이 항상 먼저다. 사용자 확인 한 번으로 상위 금지를 무효화하지 않는다. `approval_policy="never"`는 모든 명령 자동승인이 아니라 승인 요청 없이 실패할 수 있다는 뜻이다. 프로젝트/훅 trust를 대신 기록하지 않는다.
- 원문의 자동 push·PR·이슈·Notion·다음 작업 착수는 **사용자가 승인한 작업 범위와 외부 쓰기 권한이 있을 때만** 적용한다. 검사 pass, automode, STATE의 다음 할 일, identity 마커 자체는 새 권한이 아니다. 원격 생성·배포·다른 저장소 쓰기를 덧붙이지 않는다.
- SETUP-PENDING이면 SETUP.md를 읽되 마커만으로 자동 삭제/초기화하지 않는다. 파생 초기화가 요청된 경우에만 런북 범위로 위임한다. 없는 identity/PREFIX/Notion 페이지 ID를 추정하지 않는다.
- 기존 사용자 변경을 보존한다. 원문의 reset/restore·의존성 폴더 정리는 자동 명령이 아니다. 대상 소유권과 안전한 복구 가능성을 확인하고 현재 작업 범위에서만 실행한다.
- 시작 마커/훅은 `.codex/hooks.json`과 `python scripts/starter.py status`를 쓴다. 메인은 status 실행도 경량 위임한다. Claude 배너·statusline.sh·RTK 자동 hook 실행을 Codex에 있다고 가정하지 않는다.
- 상태는 `.codex/perf/units/*.status`의 보조 기록이다. Codex 화면 상태줄의 자동 표시와 Claude 대시보드 파서는 제공하지 않는다. 병렬 reviewer는 각자 unit+reviewer 접미사의 상태 파일을 사용한다(판정 파일의 unit 자체는 유지).
- perf/recall은 Codex 이벤트·rollout을 사용한다. Claude message.id/async_launched나 비용 집계식을 재사용하지 않는다. SessionEnd는 포인터만 수집하며 별도 모델을 자동 실행하지 않는다.
- 상대 경로는 저장소 루트 기준이다. 공유 docs는 사실·결정·다음 작업을 전달하지만 Claude와 Codex의 원시 대화/승인/리뷰 파일을 자동 공유한 것으로 취급하지 않는다.
