# CA 발급 체인 오류 경고 등록

## 현재 확인본과 범위 — 비교 정보와 경고만 표시

> 지금 내가 방금 test.com 발급했는데 또 실패야. 실제로는 발급되었는데 실패라고 떠. 계속 발급에 성공했는데 실패라고 띄우는 부분 다 수정 필요해. 경고만 표시하면되고 CA에서 발급했는데 실패라고 표시하는것은 안됨.

CA가 issued라고 확인된 사실과 후속 수집·검증·인벤토리 등록을 분리한다. 기존 issued 상태는 "CA 발급 완료 · 결과 확인 필요", completed는 인벤토리 등록 완료다. 읽을 수 있는 응답은 원본+비교 경고로 등록한다. 파싱·수집·저장 실패로 등록하지 못했을 때도 CA 발급완료 사실과 주문 code를 보존하고 같은 code GET으로만 재수집한다. CA issued 관측을 수집/등록 전에 별도 감사 트랜잭션으로 보존한다. DB 자체가 쓰기를 받지 못하는 순간에는 관측을 영속화할 수 없다는 한계를 정직하게 구분한다.

확인된 issued 이후 연결·인증·GET·식별자·일시적인 ready/pending 응답은 발급 실패로 환원하지 않고 수집 경고로 표시한다. 실제 CA 종결/거절과 접수 불명까지 성공으로 위장하지 않는다. 과거 failed 이벤트는 삭제하지 않고 현재 CA issued 상태와 "당시 처리 오류"를 구분한다. test.com 주문 da5ac750-4b3f-4b75-9bd1-8888268e29f7 / CA1788845931267 및 기존 주문906601da-799a-4f70-beb1-adbfa81cc2f0 / CA1788844640717 복구는 B에 포함한다.

이 절이 앞선 범위와 성공 기준 2 및 위임장 중 leaf 불일치 차단 정책을 대체한다. 이전 문구는 변경 이력이며 현재 요구사항이 아니다.

> 차단기능 만들지말고 경고랑 정보만 충분히 표시해, 예를들면 요청한 기간은 이만큼인데 이렇게 나왔다거나 요청한 도메인과 나온도메인, 해당 인증서의 체인과, 실제 같이 전달된 체인 등등 쉽게 비교되도록 표시하기.

읽을 수 있는 발급 leaf는 CSR 공개키·SAN·기간·키/체인 검사 불일치가 있어도 원본과 함께 등록하고 비교 결과와 경고를 저장한다. 완료/등록과 검증 상태는 별개로 표시한다. 요청 기간과 실제 NotBefore/NotAfter/일수, 요청 DNS와 실제 SAN(CN 별도), 요청키/CSR 공개키 지문과 실제 알고리즘·크기·일치 결과, leaf issuer/AKI와 CA가 전달한 각 chain의 subject/issuer/SKI·fingerprint·서명 연결 결과를 비교한다. 확인하지 못한 전체 체인을 추정하거나 조회·대체하지 않는다.

기존 개인키는 실제 leaf 공개키와 일치할 때만 certificate_id를 연결한다. 불일치와 확인불가는 경고/정보로 표시하고 자동 배포는 추가하지 않는다. ASN.1 파싱불가 등 실제 인증서로 읽을 수 없는 응답과 개인키가 섞인 입력은 일반 검증 불일치로 취급하지 않으며 기존 형식·보안 처리 한계를 명확히 보고한다. 원문 보존, 추가 CA POST 금지, 후속 이벤트에도 비교/경고 지속, 자기 변경만 커밋, 검토 전 D 반영 금지는 유지한다.

수정된 성공 기준 2: CSR 공개키·SAN·기간/키 불일치는 등록 결과와 분리된 경고 및 요청/실제 비교 정보로 보존한다. 기존 개인키를 불일치 leaf에 일치한다고 연결하지 않는다. 정상 결과에는 잘못된 경고를 만들지 않는다.

## 대체된 이전 지시 — 아래는 이력이며 현재 정책이 아님

### 이전 사용자 확인본

> 체인보정은 하지마. CA 가 잘못된 체인을 주는것은 CA의 문제이기 때문에 검증은하고 경고는 하되 임의 수정하지 않음

> 발급된 인증서는 등록하고, 체인 오류 경고 표시

### 이전 범위

발급 인증서 leaf의 CSR 공개키, SAN/도메인, 유효기간 검증은 기존처럼 등록을 차단한다. CA가 보낸 chain의 서명 검증은 수행하되 chain만 실패하면 발급 leaf와 CA 원본 chain을 보존하고 인증서를 등록한다. 자동 보정, 체인 재정렬, 다른 체인 조회 및 대체는 하지 않는다. 오류는 구조화된 경고로 저장하고 발급 처리 이력, 인벤토리 목록, 인증서 상세에서 지속 표시한다. 기존 조회형 위험도 판정과 별개로 발급 시 관측한 사실을 표시한다.

기존 issuance_order_events에 chain_warning 이벤트를 저장하고 연결된 발급 주문의 certificate_id로 목록/상세에서 조회한다. DB 마이그레이션이나 새 네트워크 경로 없이 기존 트랜잭션·감사 경로를 재사용한다. CA 응답 chain 원문을 변경하지 않고 보존한다. 경고에는 원문 인증서·개인키·토큰을 넣지 않는다.

### 이전 범위 밖

신규 CA 주문 POST, 기존 주문 재발급, DB 직접 상태 위조, CSR/SAN/기간 검증 완화, 체인 자동 보정 및 AIA 다운로드, 임의 신뢰 설정, 새 가입자/연락처 생성, 추가 구매, E 배포, 무관 서비스 변경, push는 금지한다. 기존에 등록된 인증서는 삭제하거나 다시 쓰지 않는다.

### 이전 성공 기준

1. leaf 검증은 통과하지만 CA 원본 chain 서명이 틀린 응답을 원문 그대로 등록하고 completed 및 certificate_id를 생성한다. 경고는 코드와 사람이 읽는 사유로 남으며 재조회 후에도 유지된다.
2. CSR 공개키, SAN, 기간 오류는 chain 상태와 관계없이 계속 issue_failed이며 인증서가 등록되지 않는다. 정상 체인에는 잘못된 경고를 만들지 않는다.
3. 발급 처리 이력, 인벤토리 목록과 인증서 상세에서 체인 경고가 보인다. 일반 오류나 정상 위험도 표시 때문에 경고가 숨겨지지 않는다.
4. 기존 코드가 있는 주문 재처리는 같은 CA code GET만 사용하며 추가 POST는 0이다. 이벤트·인증서·주문 업데이트의 기존 원자성 및 감사 기록을 유지한다.
5. 관련 단위/DB 회귀 검사, API 계약과 UI 타입/빌드, 실제 브라우저 표시를 검증한다. D에는 대응 소스에 이번 변경만 반영하고 기존 DB·키·설정·CA 프록시 override·다른 서비스를 보존한다.
