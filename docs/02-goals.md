# 02 — 최종 목표

## 최종 목표 (한 문장)

폐쇄망 기업이 단일 VM 또는 Docker Compose로 설치한 뒤, 조직에 흩어진 TLS 인증서를 자동으로 발견해 하나의 인벤토리로 보고 만료 위험을 사전에 파악할 수 있게 한다.

## 성공 기준 (측정 가능)

1. CIDR 대역과 포트를 입력하면 스캔 Job이 생성되고, 도달 가능한 TLS 엔드포인트의 인증서가 인벤토리에 저장된다.
2. 같은 인증서가 여러 위치에서 발견되어도 Certificate 레코드는 1개이며, CertificateLocation이 N개로 연결된다. 동일 파일 재업로드 시에도 중복 레코드가 생기지 않는다.
3. 대시보드에서 7/30/60/90일 이내 만료 및 이미 만료된 인증서 수를 확인할 수 있고, 각 숫자를 눌러 해당 목록으로 이동한다.
4. 인증서 상세 화면에서 Subject, SAN, Issuer, 유효기간, 키 알고리즘·길이, 서명 알고리즘, 체인, 설치 위치 목록을 확인할 수 있다.
5. 로그인·로그아웃·로그인 실패·인증서 등록·데이터 내보내기가 모두 감사 로그에 기록되고, 사용자·이벤트 유형·기간으로 조회된다.
6. 인증서 10,000건 상태에서 목록 API가 2초 이내, 대시보드 요약 API가 3초 이내 응답한다.
7. `docker compose up`만으로 개발환경이 기동되고, 인증서 업로드부터 상세 조회까지 흐름이 동작한다.

## 마일스톤

### M1 — 목업 승인

완료 조건: `mockup/index.html`의 대시보드·인증서 목록·인증서 상세·Discovery 4개 화면을 사용자가 확인하고 승인한다.

### M2 — MVP 동작 (Phase 1)

완료 조건:

- Go 백엔드 + PostgreSQL + Next.js 프론트가 Docker Compose로 함께 기동된다
- 로그인 → 인증서 업로드 → 파싱 → fingerprint 중복 판정 → DB 저장 → 목록 표시 → 상세 표시 → 감사 로그 기록의 전 흐름이 동작한다
- CIDR 입력 스캔으로 인증서가 자동 수집되어 인벤토리에 들어온다
- 만료 대시보드가 실제 데이터로 채워진다
- Unit / Integration / API / Migration 테스트가 통과한다

### M3 — Phase 1 완료

완료 조건:

- 위 성공 기준 1~7이 모두 검증된다
- OpenAPI 문서가 자동 생성된다
- 보안 점검 통과: 개인키 평문 저장 없음, 로그에 민감정보 없음, 전 API 권한 검사, 보안 헤더 적용
- 설치·운영 문서(README)와 장애 복구 절차가 작성된다
