# 릴리즈 노트 — 템플릿 원본 전용

이 폴더는 Duet Starter 통합본 **기계 자체**의 변경 이력을 버전별로 남기는 자리다. 파일 하나가 버전 하나이고,
이름은 `vX.Y.Z.md` 다. 제품 기능 이력이 아니라 규칙·에이전트·스킬·훅·`scripts/` 가 어떻게 달라졌는지를 적는다.
기존 Claude 릴리스 노트는 원래 이력으로 보존한다. 통합 `SETUP.md`는 이 폴더를 자동 삭제하지 않는다.
파생 프로젝트는 과거 노트를 현재 실행 지침으로 읽지 않고, 제품 릴리스 이력과 구별한다.
이전 저장소 이름의 v2는 계보명이다. 이 폴더의 의미 버전과 독립이므로 통합 호환 변경은 v3.0.0으로 기록한다.

`docs/STATE.md` 와 역할이 다르다. STATE 는 **지금 무엇이 참인가**만 담고 이력을 쌓지 않는다(`.claude/skills/handoff/SKILL.md` §1).
쌓이는 이력은 여기 산다.

## 언제 쓰나

Claude의 `/handoff` 또는 Codex의 `$handoff`가 **템플릿 기계를 바꾼** 작업 단위를 마무리할 때,
`docs/STATE.md`와 **같은 커밋**에 새 노트를 넣는다.
"기계"는 규칙·에이전트·스킬·훅과 settings·`scripts/` 다. 오타나 서식만 고쳐 규칙의 뜻이 하나도 바뀌지 않은 세션은 건너뛴다.
각 실행기의 handoff 스킬을 따르며 형식과 번호 규칙은 이 파일이다. 프로젝트 제품 릴리스 발행 권한까지 뜻하지 않는다.

## 버전 규칙

- **MAJOR** — 파생 프로젝트가 그냥은 따라올 수 없는 변경. `SETUP.md` 단계 구조, 양쪽 identity 스키마,
  동기화 manifest 의 호환이 깨질 때.
- **MINOR** — 규칙·에이전트·스킬·훅이 새로 생기거나 **행동이 달라질 때.** 대부분이 여기다.
- **PATCH** — 행동은 그대로고 문구·오타·문서 정리만 할 때.
- 현재 버전은 이 폴더에서 **가장 큰 `vX.Y.Z.md`** 다. 버전 값을 다른 어디에도 저장하지 않는다 —
  손으로 적은 값은 갱신을 한 번 놓치는 순간 거짓이 된다(`.claude/conventions/work-order.md` §5 와 같은 선).
- 목록 파일도 만들지 않는다. `ls docs/releases/` 가 항상 최신이다.

## 노트 형식

새 항목은 **새 파일**로 추가한다 — 기존 노트를 고쳐 쓰지 않는다. 지나간 버전의 기록은 그대로 둔다.

```markdown
# v9.9.9 — 2026-01-01

한 줄 요약 — 이 버전이 무엇을 바꿨나.

## 바뀐 것
- `RN-042` 무엇을 바꿨나 — 왜 바꿨나. `경로/파일.md` [TPL-20260101-001-A]

## 파생 프로젝트가 할 일
없음.
```

- 항목마다 **무엇이 바뀌었나**와 **왜**를 한 줄에 함께 적는다. 무엇만 적힌 줄은 다음 사람에게 아무것도 알려주지 않는다.
- Work Order ID 가 있으면 대괄호로 붙인다 — `git log --grep=<ID>` 로 커밋까지 되짚을 수 있다.
- '파생 프로젝트가 할 일'은 비우지 말고 없으면 `없음.` 한 줄을 남긴다. 빈 절은 "안 적은 것"과 구분되지 않는다.

## RN 코드

- 형식은 `RN-<세 자리>`, **저장소 전역 연속 번호**다. 버전이 올라가도 1 로 되돌아가지 않는다.
- 한 번 쓴 번호는 재사용하지 않는다. 항목을 지워도 그 번호는 비워 둔다.
- 다음 번호는 파일에서 유도한다 — 카운터를 어디에도 저장하지 않는다. 저장소 루트에서 마지막으로 쓴 번호를 본다:

  ```bash
  grep -ho 'RN-[0-9][0-9][0-9]' docs/releases/v*.md | sort -u | tail -1
  ```

  글로브가 `v*.md` 인 이유는 이 파일의 형식 예시(`RN-042`)까지 세면 번호가 튀기 때문이다 — 노트만 센다.
