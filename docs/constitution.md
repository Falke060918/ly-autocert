# constitution — 프로젝트 불변 원칙

이 파일은 **모든 위임장과 검증 판정이 대조되는 기준**이다 (design/00·03).
스펙 초안은 `$clarify`가 이 파일과 충돌하는지 검사하고, reviewer 판정은 이 원칙 위반을 품질보다 먼저 본다.
구성: 상단 "기본 원칙"은 템플릿 동봉분이라 파생 프로젝트에서도 지우지 않는다.
하단 "이 프로젝트의 원칙"은 파생 프로젝트 소유 — 템플릿 동기화가 덮어쓰지 않는다.

## 기본 원칙 (템플릿 동봉 — 파생 프로젝트에서도 유지)

### 1. 글이 아니라 장치
"지키라"고 적는 대신 구조가 대신 지키게 한다 — 어기면 멈추고(deny·샌드박스), 잊으면 자동으로 뜨고(훅),
안 하면 성적표에 찍힌다(계측). 새 규칙을 제안할 때는 "이걸 강제할 장치가 무엇인가"를 함께 답한다.

### 2. 위임 4원칙 (Karpathy)
1. **가정을 명시하고, 모호하면 선택지를 제시한다.** 일꾼은 스스로 정한 가정을 보고서에 적는다.
   갈림길의 판별과 처리는 실행기별 '복창과 검증' 규칙(Claude: `CLAUDE.md`,
   Codex: `.codex/conventions/operating-principles.md`)과 같다 — 두 해석의 산출물이 실제로 달라지고
   파괴적·비가역일 때만 되묻고, 되돌리기 쉬우면 "A로 간다"를 선언하고 진행하며, 산출물이 달라지지 않으면
   기본값으로 닫고 가정 목록에 남긴다(5번 표 '가정' 항목의 검증과 같은 선). 무인 모드의 1계층 기본값
   닫기(기록 동반)도 위반이 아니다.
2. **요청된 기능만 만든다.** 투기적 추상화(나중에 쓸지도 모른다며 미리 만드는 구조) 금지.
3. **변경된 모든 줄이 요청으로 추적 가능해야 한다.** "어느 요청 때문인가"에 답 못 하는 줄은 2번 위반이다.
4. **명령형 절차 대신, 검증 가능한 성공 기준으로 위임한다.** 절차는 일꾼이 정하고, 검사관은 기준만 대조한다.

### 3. 의도는 요약하지 말고, 대조하라
- 위임장에는 **사용자 원문 인용·성공 기준 2~3줄·하지 말 것·배관**의 4종 세트가 의무다 (경량 위임만 면제).
- `[확인 필요]` 표식이 남은 스펙은 위임 불가 — grep이 막는다 (`$clarify`).
- 검증은 코드 품질보다 먼저 성공 기준·사용자 원문과 산출물을 대조한다.

### 4. 완료 보고는 증거가 아니다 (watch like a hawk)
판정 기준은 항상 산출물 자체다: 커밋이 실제로 존재하는가(`git log`), diff 범위가 요청과 일치하는가.
staged-미커밋은 완료가 아니고, idle은 완료가 아니다.

### 5. 검증 점검 4항 (실패 모드의 뒷면)

| 실패 모드 | 검증 질문 |
| --- | --- |
| 가정 (묻지 않고 정함) | 보고서에 가정 목록이 있는가? 없는데 갈림길이 있었다면 탈락 |
| 비대화 (모호한데 안 물음) | `[확인 필요]`가 남았는데 진행했는가? |
| 무관 수정 (요청 밖 변경) | diff의 모든 줄이 요청으로 소급되는가? |
| 반박 부재 (나쁜 요청도 수행) | 요청의 문제를 발견하고도 침묵했는가? 보고서에 "이견 없음/있음" 필드 의무 |

`docs/00-spec.md`, `docs/ROADMAP.md`, `docs/STATE.md`에는 발급·배포·에이전트와

우선하며, 아래 보존 문구를 이유로 승인된 작업을 되돌리거나 재승인을 요구하지 않는다.

### 이전 프로젝트 규칙 원문

# 프로젝트 고유 규칙 — INHERIT_AutoCert

폐쇄망·레거시 환경용 온프레미스 인증서 라이프사이클 관리(CLM) 플랫폼. 아래는 이 저장소에만 적용되는 규칙이다.

## 기술 스택 고정
기술 스택은 `docs/00-spec.md` **11장의 고정값**이다. 이유 없이 변경하지 않는다.
- Backend: Go / REST API / OpenAPI 3 / PostgreSQL / SQL migration / 비동기 작업 큐
- Frontend: Next.js + React + TypeScript
- 배포: Docker, Docker Compose (이후 Helm Chart / Kubernetes)
- 관측성: OpenTelemetry, Prometheus Metrics, 구조화 JSON 로그, Trace/Request ID

변경이 필요하면 **변경 이유 · 장점 · 단점 · 마이그레이션 영향 · 운영 복잡도**를 먼저 문서화한 뒤 사용자 승인을 받는다.
"더 익숙해서", "요즘 이게 표준이라서" 같은 사유는 변경 근거가 아니다.

## 보안 하드 규칙
인증서 제품이므로 아래는 권장이 아니라 **위반 시 되돌리는 규칙**이다.
1. **개인키 평문 저장 금지** — 저장 민감정보는 암호화하고, 비밀번호는 강력한 단방향 해시로만 보관한다.
2. **자체 암호 구현 금지** — 검증된 표준 라이브러리만 쓴다. 해시·서명·암호화·난수 생성을 직접 만들지 않는다.
3. **인증서·개인키를 로그에 출력 금지** — 디버그 로그, 에러 메시지, 스택트레이스 어디에도 남기지 않는다.
4. **테스트 코드에도 민감값 하드코딩 금지** — 픽스처는 테스트 전용으로 생성하고, 실제 키·인증서를 커밋하지 않는다.
5. **모든 변경 API는 감사 로그를 생성한다** — 생성·수정·삭제·내보내기는 예외 없이 AuditEvent를 남긴다.
6. **모든 API는 권한 검사를 거친다** — 인증만으로 통과시키지 않고 요청마다 역할 기반 권한을 확인한다.

## 결정론적 자동화
핵심 인증서 작업(발견·발급·배포·갱신·폐기)은 AI가 아닌 **명시적 상태 머신 + 정책 엔진**으로 실행한다.
재시도 가능하고, 중복 실행에 안전하며, 상태를 추적할 수 있고, 롤백·감사가 되어야 한다.
**AI가 생성한 셸 명령을 직접 실행하지 않는다.** AI는 보조(설명·요약·추천)에만 쓰고 실행 경로에 두지 않는다.

## 범위 통제 — Phase 1만
이번 범위는 **Phase 1(인증서 인벤토리)** 뿐이다. 상세 항목은 `docs/01-plan.md`에 있다.
`docs/00-spec.md` 16장의 제외 목록과 `docs/01-plan.md`의 "이번 범위에서 제외"에 해당하는 기능은
**요청받아도 Phase 1이 완성되기 전에는 구현하지 않는다.** 요청이 오면 제외 항목임을 한 줄로 알리고,
Phase 1을 먼저 끝낼지 범위를 넓힐지 확인 1회를 받는다. 설계상 확장점만 남기는 것은 허용한다.
