# MAP — 코드베이스 구조·명령 캐시
확인일: 2026-08-09

## 저장소 구조
- `backend/` — Go 백엔드
  - `cmd/server/main.go` — 엔트리포인트. config 로드 → 기동 경고 출력(`logStartupWarnings`: `cfg.Warnings` + `cfg.NotifyChannelErrors`를 채널·사유만 WARN, 값은 안 싣는다) → DB 연결 → 마이그레이션 → 고아 서버 Job 회수(`ReapOrphanedServerScanJobs`) → 백그라운드 루프 기동 → HTTP 서버 구성·기동(**순서 고정**: 핸들러에 알림 채널 어댑터를 주입해야 하므로 `api.NewServer`는 `startNotify` 뒤에 온다 — `api.WithNotificationChannels(notifyChannels)` + `api.WithSweepDefaults(sweepDefaults(cfg.Sweep))`). `SENSOR_CA_ENC_KEY` 설정 시에만 sensorgw 리스너(8443)+리스 reaper 기동 — 미설정이면 로그 1줄 남기고 8443을 아예 열지 않음(zero-config 무영향), 종료 시 두 서버 모두 graceful shutdown. **센서 게이트웨이 실패는 코어를 죽이지 않는다**: 구성 실패(SAN 없음 등)·리스너 실패 모두 `startSensorGateway`가 경고 로그 후 게이트웨이만 비활성화하고 8080은 계속 뜬다(어떤 SENSOR_* 조합에서도 exit 없음)
  - `cmd/server/wiring.go` — 백그라운드 루프 배선. `notifyStore` 어댑터 하나가 `*store.Store`를 notify의 세 인터페이스(Scheduler/Dispatcher/Inbox) 전부로 잇는다(notify는 store를 import하지 않는다). `startNotify`는 스케줄러+디스패처를 띄우고(`NOTIFY_ENABLED=false`면 스케줄러가 로그 1줄만 남기고 둘 다 미기동), 채널 4종(email/webhook/syslog/inbox)을 만들어 `cfg.NotifyChannelErrors`와 함께 디스패처에 넘긴다 — 딥링크는 `NOTIFY_BASE_URL`(비면 생략). `startSweepScheduler`는 `discovery.NewManager(st).UseSweepOptions(sweepOptions(cfg.Sweep))`로 **API가 쓰는 Manager와 별도 인스턴스**를 띄운다(스케줄러는 API Manager와 상태를 공유하지 않는다). 두 stop 함수 모두 sensorgw.StartReaper와 같은 규약이라 main.go가 `defer`로 잡는다. **알림·스윕 설정 오류로 코어 API가 죽지 않는다** — 생성자는 에러를 내지 않고 채널 단위 비활성으로만 드러난다(env 전무/오값/전부 false 4조합에서 `/healthz` 200 실증). `startNotify`는 `(stop, *notifyChannels)`를 반환하고 그 `notifyChannels`가 `api.NotificationChannels`(Status/SendTest) 구현이다 — **`NOTIFY_ENABLED=false`여도 non-nil**(전 채널을 그 사유로 비활성 보고, 테스트 발송은 skipped). 사유 우선순위는 NOTIFY_ENABLED → `cfg.NotifyChannelErrors`(채널당 **첫 사유만** 기록됨) → `Notifier.Enabled()`. 상태 응답은 {channel,enabled,reason}뿐이라 설정값이 실릴 자리가 없고, 테스트 발송 에러는 `redactConfigValues`가 WEBHOOK_URL·HMAC 시크릿·SMTP 비밀번호를 마커로 치환한 뒤 응답·감사로 나간다(4조합 실증: 미설정/전 채널 설정/`NOTIFY_ENABLED=false`/`SMTP_PORT` 오값)
  - `cmd/sensor/main.go` — 센서(원격 수집기) 바이너리 엔트리포인트. `enroll`/`run` 서브커맨드, slog JSON 로그. 정적 크로스 빌드: `CGO_ENABLED=0 GOOS=linux|windows GOARCH=amd64 go build ./cmd/sensor`
  - `internal/config/` — 환경변수 기반 설정 (`SESSION_TTL` 기본 8h, `BOOTSTRAP_ADMIN_USERNAME`/`_PASSWORD`, `SENSOR_CA_ENC_KEY` hex 64자 — 센서 CA 개인키 봉인 키, 미설정이면 첫 센서 생성 시점에만 오류. 형식 오류는 기동 실패가 아니라 `Config.SensorConfigError`로 실려 나가고 게이트웨이만 꺼진다. `SENSOR_LISTEN_ADDR` 기본 ":8443", `SENSOR_ADVERTISED_HOSTS` 콤마 구분 DNS/IP 혼용 — 게이트웨이 서버 인증서 SAN, IP는 net.ParseIP로 분류)
    - 알림·스윕 변수군도 여기서 읽는다 — `NOTIFY_*`(Enabled/ScanInterval 1h/FirstRun seed|send/RetentionDays 180/BaseURL)·`SMTP_*`(PASSWORD_FILE이 PASSWORD보다 우선)·`WEBHOOK_*`·`SYSLOG_*`·`SCAN_SWEEP_*`(RatePPS 10·Concurrency 8·ChunkEndpoints 4096·ChunkGap 5s·MaxDays 30·StallAfter 10m). **설정 오류는 기동 실패가 아니다**: 채널 설정 오류는 `Config.NotifyChannelErrors[채널]`(해당 채널만 비활성, 사유에 secret 금지), 값 오류·위험 설정은 `Config.Warnings`(기본값 폴백 후 경고) — 코어 API는 어느 쪽이든 정상 기동(sensorgw 격리와 같은 규약)
  - `internal/db/` — PostgreSQL 연결 + 마이그레이션 적용. DB 테스트는 `TEST_DATABASE_URL` 설정 시에만 실행(미설정 시 스킵)
  - `internal/domain/` — 핵심 데이터 모델 Go 타입 (00-spec 12장 기준: Certificate/CertificateLocation/Target/AuditEvent + User/Role 6종 + 상태 enum. `sensor.go` — Sensor/SensorStatus·JobType('scan' 폐쇄)·ExecutorType·ExecutorScopeServer)
  - `internal/certparse/` — 인증서 파서 (PEM 체인·DER, crypto/x509만). 개인키 검출 시 `ErrPrivateKeyFound`로 전체 거부. 새 포맷(P7B/PFX)은 `decoders` 목록에 추가. SKI/AKI를 소문자 hex로 추출(체인 매칭 키)
  - `internal/store/` — PostgreSQL 영속화. fingerprint 중복 판정 upsert + 감사 이벤트 + 목록·상세 조회(검색·필터·정렬·페이지네이션 — 정렬 컬럼은 화이트리스트, 만료·self_signed·unowned 필터는 파생 계산) + `certificates_summary.go`(대시보드 집계 단일 쿼리 — expiring_* 누적값) + `certificates_chain.go`(상세 응답 chain 배열 — 자신→루트, AKI=SKI 우선·DN 폴백 매칭, 미보유 상위는 stored=false, upsert가 중복 재업로드 시 키 식별자 백필) + `certificates_export.go`(목록 조건 기반 전체 조회 + certificate.export 감사를 같은 트랜잭션으로 — 감사 실패 시 내보내기도 실패, 상한 50000행). text[]는 SQL 쪽 `string_to_array(chr(31))`, int[]는 `string_to_array(',')::int[]`, inet은 `::inet`/`host()` 캐스트로 변환 (database/sql 제약). `discovery.go` — scan_jobs 상태 머신(생성 시 total_endpoints 기록 — 생성 응답과 상세 조회가 일치) + 서버 기동 시 고아 회수 `ReapOrphanedServerScanJobs`(executor_type='server'의 pending/running을 error='server restarted'로 failed 처리 + 건당 감사, 센서 Job 불간섭 — 서버 Job은 인프로세스 goroutine이 유일 실행 주체라 재큐잉해도 집어갈 디스패처가 없다) + 발견 인증서 인벤토리 반영(targets 아비터는 0010의 (executor_scope, ip) 부분 유니크 인덱스 — 서버 경로 스코프 'server', ON CONFLICT upsert로 동시 실행 안전). `sensorjobs.go` — 센서 pull 리스 상태 머신(FOR UPDATE SKIP LOCKED 리스 90s TTL·전이 가드 leased→running→completed/failed·하트비트 연장·만료 reaper) + Observation 멱등 배치(scan_job_endpoints PK 아비터 ON CONFLICT DO NOTHING, 스코프 'sensor:<uuid>'). 진행률 카운터 규약: 하트비트는 보고값을 GREATEST로 병합(리스 연장과 같은 UPDATE), 관측 배치는 scan_job_endpoints 집계로 **절대값 재계산**(증분 아님 — 두 경로 이중 계상 방지), certificates_new만 증분. `sensors.go` — Phase 3a 센서 영속화(0009): 생성=1회용 토큰 발급(평문은 반환만, DB엔 SHA-256 hex·24h) / enroll은 단일 UPDATE 원자 소진(pending+해시+미만료, 실패도 감사) / fingerprint로 active 조회(mTLS 대조)·원자 교체(renew)·disable(pending 토큰 회수 겸용) / sensor_ca 단일 행 Save(중복은 ErrSensorCAExists)·Load — 감사 sensor.token.issue/enroll/renew/disable 전건 동일-tx. `sweeps.go` — 전 포트 백그라운드 스윕(0013): 부모 `scan_sweeps` + 자식 청크는 기존 `scan_jobs` 행 재사용(job 상태 enum 불변). 청크는 순수 함수 `WaveOrderPorts`(프리셋→1-1023→1024-49151→49152-65535)·`ChunkForSeq`(포트-메이저 격자, seq→엔드포인트 결정론적 재생)로 계산해 DB에 물리 저장하지 않음. `CreateSweep`은 ETA>`MaxDays`(기본 30)면 `*SweepTooLongError`(실제 일수 포함, 핸들러 422). `DispatchNextChunk`는 스윕 행 FOR UPDATE 단일 tx — 진행 중 자식이 있으면 발주 안 함(동시 청크 최대 1), 아비터 `uq_scan_jobs_sweep_seq_active` 충돌은 정상 흡수, failed seq는 총 2회까지 재발주(소진 시 스윕 failed·소진 없으면 completed). **진행률 컬럼 없음** — 자식 Job 집계로 파생(failed 행 제외로 재시도 이중 계상 방지). pause/resume/cancel은 발주자만 제어(진행 중 청크 완주). `RefreshSweepStalls`는 센서 스코프 스윕의 `stalled_since`만 세팅/해제(신규 종료 상태 없음). store는 discovery를 import하지 않음(의존 방향 discovery→store) — 포트 목록·청크 함수는 인자로 주입. `notifications.go` — 알림 파이프라인 영속화(0012): 정책 CRUD(감사 notification.policy.create/update/delete 동일-tx, 이름 충돌은 `ErrNotificationPolicyNameTaken`) / 탐지는 `unnest(p.thresholds)×certificates` 세트 기반 단일 `INSERT…SELECT … ON CONFLICT (dedup_key) DO NOTHING RETURNING`(새 이벤트만 팬아웃 → 중복 발송 구조적 불가). 판정은 **저장된 status가 아니라 not_after**(status는 revoked/replaced 제외 필터 전용), CA 포함, dedup_key에 정책 id 없음(정책이 겹쳐도 이벤트 1건·수신자 합집합). `RunNotificationTick`은 `pg_try_advisory_xact_lock(x'6e6f74696679')` 단일 tx(못 잡으면 조용히 skip), seed 모드는 suppressed 적재만 하고 팬아웃 생략. 팬아웃은 (이벤트,채널)별 수신자 합집합 — owner 해석 실패 시 static 폴백, 그것도 없으면 `skipped`+사유 행(조용히 사라지지 않음). 리스는 `FOR UPDATE SKIP LOCKED`(TTL 2m), 실패는 1m×2^(n-1)·상한 1h 백오프 후 5회째 `failed`, 고아 리스는 `pending`으로 회수(스캔 Job의 failed 회수와 반대). payload는 공개 필드 7종 스냅샷 전용(인증서 원문 경로 없음). store는 notify를 import하지 않고 notify도 store를 import하지 않음(양쪽이 채널 문자열 상수를 각자 보유, 연결은 `cmd/server/wiring.go`의 `notifyStore` 어댑터가 담당 — `MarkDeliveryFailed`만 시그니처가 달라 반환값 `*DeliveryAttempt`를 버린다)
    - 만료 조회·집계(summary 7/30/60/90d, 목록 필터 expires_within_days)와 만료 알림(0012 + `internal/notify`)은 별개 경로 — 알림 탐지는 저장된 status가 아니라 `not_after`로 판정한다(status는 revoked/replaced 제외 필터로만 씀)
  - `internal/discovery/` — 에이전트리스 네트워크 TLS 스캔. `scanner.go`(crypto/tls 핸드셰이크로 서버 인증서 체인 수집, IP/CIDR·포트 Expand, InsecureSkipVerify는 **수집 전용**, 호스트명은 역방향 DNS 1s → 리프 CN 폴백. **store/db 비의존 유지** — Phase 3a 센서(원격 수집기) 바이너리 재사용 전제) + `manager.go`(비동기 Job: 워커풀·상태 머신, 백그라운드는 `context.Background()`. SensorID 지정 시 executor_type='sensor' pending 생성만 — 서버 goroutine 미기동, 센서가 pull 리스) + `limiter.go`(스캔 속도 억제: `RateLimiter`는 golang.org/x/time/rate 토큰 버킷(burst 1, dial 직전 `Wait` 호출용, pps<=0 무제한·`MaxRatePPS`=1000 클램프+경고), `InterleaveByHost`는 호스트별 라운드로빈 재배열로 연속 프로브가 같은 IP를 때리지 않게 함 — IPS 포트스캔 오탐 억제, **결정론 필수**(랜덤 셔플 금지, 재시도 멱등성). 기본값 상수 단발 50pps/동시성 20·스윕 10pps/동시성 8/청크 공백 5s. 서버·센서 공용이며 호출자가 감싸는 구조라 `ScanEndpoint`/`Expand` 시그니처는 불변) + `ports.go`(포트 스펙 파서 `ParsePortSpec` — 콤마 나열·범위 `8000-9000`·프리셋 3종(web 6 / common 26 / all 65535)을 혼용 파싱, 중복 제거 후 오름차순, 기본값 `DefaultPortSpec = "common"`. **`Expand` 앞단의 순수 함수**라 Expand/ScanEndpoint 시그니처 불변 → 센서 측 영향 0(서버가 정수 목록으로 전개해 리스에 실음). STARTTLS 승격 포트(25·587·110·143·389·5432·3306·1433·21·3389)는 스캐너가 implicit TLS 전용이라 **프리셋에서 의도적 제외** — 넣으면 전건 실패 노이즈만 남는다. `all`은 스윕 전용, 단발 스캔이면 400) + `sweep.go`(대역 스윕 스케줄러 `Manager.StartSweepScheduler(ctx) (stop func())` — sensorgw.StartReaper와 같은 정지 규약, 설정 주입은 `NewManager(st).UseSweepOptions(SweepOptions{…})`(config.SweepConfig와 1:1, `Enabled=false`면 로그 1줄 남기고 아예 안 뜬다). 루프: 활성 스윕(queued/running) 목록 → 진행 중 청크가 있으면 DB 호출 자체를 생략 → `store.DispatchNextChunk`에 **청크 계산 함수 주입**(웨이브 우선순위 `presetCommon`→1-1023→1024-49151→49152-65535를 `store.WaveOrderPorts`에 넘기는 것이 이 파일의 핵심 역할 — store는 discovery를 import할 수 없다) → 서버 스코프면 그 자리에서 실행, 센서 스코프면 pending으로 두고 센서가 pull. 스윕 전개(IP·포트)는 스윕당 1회 캐시(정의는 생성 시점 고정), 전개 실패는 nil 캐시라 로그도 1회. `RefreshSweepStalls`는 별도 티커(1m)). **스캔 실행 경로는 `scanAll` 한 곳**(manager.go): `InterleaveByHost` 재배열 + dial 직전 `RateLimiter.Wait` — 단발 50pps, 스윕 자식 Job은 자기 행 rate_pps. ctx 취소로 끝난 Job은 종료 상태를 찍지 않는다(다음 기동의 고아 회수 → 스윕이면 같은 seq 재발주). 실제 dial은 테스트 대역 `scanEndpoint` 변수로 교체 가능. 도달불가·핸드셰이크 실패는 조용히 실패 기록 후 계속

## 실행
- `cp .env.example .env && docker compose up --build` [unix]
- `.env` 필수 2개 = POSTGRES_PASSWORD·BOOTSTRAP_ADMIN_PASSWORD. SENSOR_CA_ENC_KEY/SENSOR_ADVERTISED_HOSTS/SENSOR_LISTEN_ADDR는 compose엔 배선돼 있으나 .env.example엔 없어 수동 추가(INSTALL 5.2). 앞의 두 개는 세트 — CA 키만 넣고 HOSTS를 비우면 SAN이 없어 게이트웨이가 경고 로그 후 비활성화된다(8080은 정상 기동, 센서만 못 붙음).
- 알림·스윕 변수(`NOTIFY_*`/`SMTP_*`/`WEBHOOK_*`/`SYSLOG_*`/`SCAN_SWEEP_*`)도 compose 패스스루만 있고 `.env.example`엔 없다 — 전부 비어도 정상(알림은 inbox만 활성, 스윕은 기본값). 목록·기본값은 INSTALL 5.2.1·5.2.2.
