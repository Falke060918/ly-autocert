# MAP — 코드베이스 구조·명령 캐시
확인일: 2026-08-11

## 저장소 구조
- `backend/` — Go 백엔드
  - `cmd/server/main.go` — 엔트리포인트. config 로드 → 기동 경고 출력(`logStartupWarnings`: `cfg.Warnings` + `cfg.NotifyChannelErrors`를 채널·사유만 WARN, 값은 안 싣는다) → DB 연결 → 마이그레이션 → 고아 서버 Job 회수(`ReapOrphanedServerScanJobs`) → 백그라운드 루프 기동 → HTTP 서버 구성·기동(**순서 고정**: 핸들러에 알림 채널 어댑터를 주입해야 하므로 `api.NewServer`는 `startNotify` 뒤에 온다 — `api.WithNotificationChannels(notifyChannels)` + `api.WithSweepDefaults(sweepDefaults(cfg.Sweep))`). `SENSOR_CA_ENC_KEY` 설정 시에만 sensorgw 리스너(8443)+리스 reaper 기동 — 미설정이면 로그 1줄 남기고 8443을 아예 열지 않음(zero-config 무영향), 종료 시 두 서버 모두 graceful shutdown. **센서 게이트웨이 실패는 코어를 죽이지 않는다**: 구성 실패(SAN 없음 등)·리스너 실패 모두 `startSensorGateway`가 경고 로그 후 게이트웨이만 비활성화하고 8080은 계속 뜬다(어떤 SENSOR_* 조합에서도 exit 없음)
  - `cmd/server/wiring.go` — 백그라운드 루프 배선. `notifyStore` 어댑터 하나가 `*store.Store`를 notify의 세 인터페이스(Scheduler/Dispatcher/Inbox) 전부로 잇는다(notify는 store를 import하지 않는다). `startNotify`는 스케줄러+디스패처를 띄우고(`NOTIFY_ENABLED=false`면 스케줄러가 로그 1줄만 남기고 둘 다 미기동), 채널 4종(email/webhook/syslog/inbox)을 만들어 `cfg.NotifyChannelErrors`와 함께 디스패처에 넘긴다 — 딥링크는 `NOTIFY_BASE_URL`(비면 생략). `startSweepScheduler`는 `discovery.NewManager(st).UseSweepOptions(sweepOptions(cfg.Sweep))`로 **API가 쓰는 Manager와 별도 인스턴스**를 띄운다(스케줄러는 API Manager와 상태를 공유하지 않는다). `startRescanScheduler`도 같은 형태의 **세 번째** 인스턴스다(`UseRescanOptions(rescanOptions(cfg.Rescan))` — 동시성만 설정 표면을 늘리지 않으려고 상수 `discovery.RescanConcurrency`를 쓴다). 다만 이쪽은 `(stop, api.RescanController)`를 반환한다 — 어댑터 `rescanController`가 `Settings()`/`RunOnce()`를 잇고 **`RESCAN_ENABLED=false`여도 non-nil**이다(꺼짐과 미배선을 화면이 구분해야 한다 — notifyChannels와 같은 규약). `RunOnce`는 **요청 ctx를 쓰지 않고 서버 수명 ctx**로 `DispatchRescanOnce`를 부른다: 202 응답과 함께 취소되면 방금 발주한 Job이 종료 상태를 못 찍고 다음 기동의 고아 회수로 넘어간다. `actor`는 아직 감사에 싣지 않는다(발주 감사는 actor NULL, origin으로만 구분). `startScanScheduleRunner`(0019 정기 스캔)는 **새 Manager를 만들지 않고 재스캔 인스턴스를 그대로 받아** `UseSweepOptions`+`UseScheduleOptions`를 얹는다 — '등록된 인증서' 정기 스캔의 '지금 실행'이 곧 재스캔 1배치 발주이므로 같은 설정·같은 진행 중 실행 추적(wg)을 공유해야 한다. 그래서 `startRescanScheduler`의 반환은 `(stop, api.RescanController, *discovery.Manager)` 3개이고, 어댑터 `scheduleController`도 `RunNow`에 **서버 수명 ctx**를 쓴다(rescanController와 같은 이유). 네 stop 함수 모두 sensorgw.StartReaper와 같은 규약이라 main.go가 `defer`로 잡는다. **알림·스윕 설정 오류로 코어 API가 죽지 않는다** — 생성자는 에러를 내지 않고 채널 단위 비활성으로만 드러난다(env 전무/오값/전부 false 4조합에서 `/healthz` 200 실증). `startNotify`는 `(stop, *notifyChannels)`를 반환하고 그 `notifyChannels`가 `api.NotificationChannels`(Status/SendTest) 구현이다 — **`NOTIFY_ENABLED=false`여도 non-nil**(전 채널을 그 사유로 비활성 보고, 테스트 발송은 skipped). 사유 우선순위는 NOTIFY_ENABLED → `cfg.NotifyChannelErrors`(채널당 **첫 사유만** 기록됨) → `Notifier.Enabled()`. 상태 응답은 {channel,enabled,reason}뿐이라 설정값이 실릴 자리가 없고, 테스트 발송 에러는 **채널 구현이 발생 지점에서 설정값을 넣지 않는 것이 1차 방어**(에러엔 변수 이름·HTTP 상태코드·오류 종류만) — `redactConfigValues`는 그래도 새는 값을 지우는 이중 안전망이다(4조합 실증: 미설정/전 채널 설정/`NOTIFY_ENABLED=false`/`SMTP_PORT` 오값). 규약은 `wiring_test.go`가 고정한다(사유 우선순위 3단 + 특징적 설정값을 넣고 Status·SendTest 결과 전체 문자열 검색)
  - `cmd/sensor/main.go` — 센서(원격 수집기) 바이너리 엔트리포인트. `enroll`/`run` 서브커맨드, slog JSON 로그. 정적 크로스 빌드: `CGO_ENABLED=0 GOOS=linux|windows GOARCH=amd64 go build ./cmd/sensor`
  - `internal/config/` — 환경변수 기반 설정 (`SESSION_TTL` 기본 8h, `SESSION_COOKIE_SECURE` 기본 false — 세션 쿠키 Secure 플래그, HTTPS 리버스 프록시 종단 시에만 true(오값은 경고 후 false 폴백). 백엔드는 프록시 뒤에서 평문 HTTP를 받아 요청만으로 HTTPS를 판별할 수 없어 자동 감지가 아니라 설정값이다, `BOOTSTRAP_ADMIN_USERNAME`/`_PASSWORD`, `SENSOR_CA_ENC_KEY` hex 64자 — 센서 CA 개인키 봉인 키, 미설정이면 첫 센서 생성 시점에만 오류. 형식 오류는 기동 실패가 아니라 `Config.SensorConfigError`로 실려 나가고 게이트웨이만 꺼진다. `SENSOR_LISTEN_ADDR` 기본 ":8443"이고 여기서 뽑은 포트가 `Config.SensorGatewayPort`(등록 명령 예시용 — api에 `WithSensorGatewayPort`로 주입), `SENSOR_ADVERTISED_HOSTS` 콤마 구분 DNS/IP 혼용 — 게이트웨이 서버 인증서 SAN. IP는 net.ParseIP, 나머지는 `isDNSName`(RFC1123) 통과분만 DNS로 받고 **포트가 붙었거나 호스트명이 아닌 항목은 경고 후 버린다** — 예전엔 ParseIP 실패분을 전부 DNS로 넣어 "10.0.0.5:9443"이 통째로 SAN에 박혔다). 기능별 하위 구조체 3종: `NotifyConfig`(NOTIFY_*/SMTP_*/WEBHOOK_*/SYSLOG_*) · `SweepConfig`(SCAN_SWEEP_*) — 스캔 제안 대역 `SCAN_SUGGESTED_NETWORKS`(콤마 구분 IP/CIDR → 정규화 문자열, 오류 항목만 버리고 경고)도 여기서 읽는다 · `RescanConfig`(RESCAN_*: ENABLED true / INTERVAL 12h·하한 1m / RATE_PPS 20 / BATCH_IPS 1024 / REPLACE_CONFIRM 2 / RETIRE_MISSES 30). 셋 다 값 오류가 기동 실패가 아니라 `Warnings` + 기본값 폴백이다
    - `ADMIN_IP_*`도 여기서 읽는다(`AdminIPConfig`: `TrustedProxies`/`Bootstrap`, 둘 다 콤마 구분 IP/CIDR → `[]*net.IPNet`). 넷마스크 없는 값은 /32·/128로 올리고, 형식 오류·호스트 비트는 **그 항목만 버리고 경고**(기동은 계속 — 오타 하나로 복구 경로까지 사라지면 안 된다). 허용 목록 자체는 환경변수가 아니라 DB다
    - 알림·스윕 변수군도 여기서 읽는다 — `NOTIFY_*`(Enabled/ScanInterval 1h/FirstRun seed|send/RetentionDays 180/BaseURL)·`SMTP_*`(PASSWORD_FILE이 PASSWORD보다 우선)·`WEBHOOK_*`·`SYSLOG_*`·`SCAN_SWEEP_*`(RatePPS 10·Concurrency 8·ChunkEndpoints 4096·ChunkGap 5s·MaxDays 30·StallAfter 10m)·`SCAN_TLS_PROBE_VERSIONS`(0020, 기본 false — SweepConfig가 아니라 `Config` 최상위다. `SCAN_SUGGESTED_NETWORKS`와 같은 자리이며 스윕 전용이 아니라 스캔 전반의 엔드포인트당 프로브 수를 정한다). **설정 오류는 기동 실패가 아니다**: 채널 설정 오류는 `Config.NotifyChannelErrors[채널]`(해당 채널만 비활성, 사유에 secret 금지), 값 오류·위험 설정은 `Config.Warnings`(기본값 폴백 후 경고) — 코어 API는 어느 쪽이든 정상 기동(sensorgw 격리와 같은 규약)
  - `internal/db/` — PostgreSQL 연결 + 마이그레이션 적용. DB 테스트는 `TEST_DATABASE_URL` 설정 시에만 실행(미설정 시 스킵)
  - `internal/domain/` — 핵심 데이터 모델 Go 타입 (00-spec 12장 기준: Certificate/CertificateLocation/Target/AuditEvent + User/Role 6종 + 상태 enum. `sensor.go` — Sensor/SensorStatus·JobType('scan' 폐쇄)·ExecutorType·ExecutorScopeServer)
  - `internal/certparse/` — 인증서 파서 (PEM 체인·DER, crypto/x509만). 개인키 검출 시 `ErrPrivateKeyFound`로 전체 거부. 새 포맷(P7B/PFX)은 `decoders` 목록에 추가. SKI/AKI를 소문자 hex로 추출(체인 매칭 키). `Describe`가 **유일한 변환 지점**이고 스캔·업로드가 공유한다 — 0018부터 `Content`(raw_der·spki_sha256·key_usage·ext_key_usage 전체·is_ca·path_len·OCSP/CRL/AIA URL)를 함께 채운다. `classify()`는 EKU 첫 매칭 1개만 쓰는 기존 동작 그대로다(certificate_type이 흔들리면 필터·위험 판정이 함께 흔들린다). `presented_chain.go`의 `AnalyzePresentedChain`은 **엔드포인트가 제시한 것만으로** 체인이 이어지는지 판정한다 — 인벤토리로 보완하지 않으며 **루트 미전송은 정상 관행이라 불완전으로 세지 않는다**(리프 혼자·중간 누락만 false)
  - `internal/certrisk/` — 인증서 위험 판정 엔진(순수 함수, DB·네트워크 비의존 — 입력은 `domain.Certificate` + 위치 축 `LocationInput` + 기준 시각뿐). **판정은 저장하지 않고 조회 시 계산한다** — 기준선이 2027·2030에 움직이므로(NIST IR 8547, CA/B Forum) 저장하면 낡는다. 만료 판정과 같은 규약이라 **마이그레이션이 없다**. `certrisk.go`가 카탈로그(`Rules()` — 코드·심각도·Scope·title·`PublicTrustOnly`)와 `Evaluate`를, `rules.go`가 규칙 구현을 갖는다. **코드 1개의 심각도는 고정**이다(강도가 갈리면 코드를 나눈다 — weak_key/key_deprecated_2030/key_strong). 심각도 4단 danger>warn>info>ok이고 `Assessment.Severity`는 최댓값(항목 0건이면 ok). Scope 2축 certificate/location 중 `legacy_tls`·`incomplete_chain`이 위치 축이다(인증서를 재발급해도 안 고쳐지고 서버 설정·배포를 고쳐야 한다).  공인 전용 규칙은 넣지 않는다 — 사설 PKI 전건이 빨간불이 되면 판정이 무시된다. `PublicTrustOnly`가 그 확장 자리이며 현재 전부 false. 규칙 15종: weak_key·weak_signature·no_san·wildcard_broad·expired_ca·chain_anomaly·legacy_tls·`incomplete_chain`(danger — 0018 `chain_complete=false`인 위치가 있을 때. **nil/NULL은 판정하지 않는다**: 0018 이전 관측·파일 업로드가 미상이라 danger로 띄우면 재스캔 전 전건이 빨간불이 된다) / wildcard·wildcard_multi_label·long_validity·self_signed(warn) / key_deprecated_2030·ed25519_key(info) / key_strong(ok). 공개 접미사 판정은 외부 목록 없이 레이블 수 휴리스틱 + 짧은 준-레지스트리 목록(`broadSecondLevels`)이다 — 폐쇄망에서 갱신할 수 없는 큰 목록을 반입하지 않는다
  - `internal/store/` — PostgreSQL 영속화. fingerprint 중복 판정 upsert + 감사 이벤트 + 목록·상세 조회(검색·필터·정렬·페이지네이션 — 정렬 컬럼은 화이트리스트, 만료·self_signed·unowned 필터는 파생 계산 + `issuer_org`(0016 `issuer_organization` 정확 일치, 빈 문자열은 IS NULL "조직 미상"·nil만 필터 없음)·`issued_by`(CA 인증서 id — findIssuer 술어의 역방향, SKI=AKI 우선·DN 폴백·자기 자신 제외)·`risk`/`risk_code`(위험 판정 — `certificates_risk.go`)·`tls_version`(0020, removed 아닌 위치의 관측 버전 EXISTS — **Go가 아니라 SQL 술어여야 total·page가 맞는다**) 필터. `ExcludeStatuses`(API `exclude_status`)는 **비면 아무것도 제외하지 않는다** — 같은 입력을 CSV 내보내기가 공유하므로 기본값을 바꾸면 아무도 요청하지 않은 내보내기 변경이 따라온다(설계 06 14.2 ⑥). 목록 원소는 `CertificateListItem`(인증서 + `last_seen_at` = max(위치 last_verified_at) 상관 서브쿼리 + `tls_versions` = 위험 판정용으로 이미 계산하던 `array_agg(DISTINCT tls_version)`를 그대로 노출(쿼리 비용 0)) — 상세·CSV엔 없고 **정렬 화이트리스트에도 넣지 않는다**(집계 파생값)) + `certificates_summary.go`(대시보드 집계 단일 쿼리 — expiring_* 누적값. 유일한 status 조건은 `WHERE status <> 'replaced'`다 — 나머지 구간은 전부 not_after 파생이라 손대지 않으면 교체된 죽은 인증서가 total·만료 임박에 섞인다. 알림은 이미 replaced를 빼므로 두 화면이 서로를 부정하게 된다) + `certificates_chain.go`(상세 응답 chain 배열 — 자신→루트, AKI=SKI 우선·DN 폴백 매칭, 미보유 상위는 stored=false, upsert가 중복 재업로드 시 키 식별자 백필) + `certificates_issuers.go`(발급기관 분포(비-CA·replaced 제외) + CA 트리 + unmatched_leaf_count. **트리는 N계층이다 — 평탄화하지 않는다**: 부모는 `findIssuerInMemory`로 한 단계만 찾고(findIssuer와 같은 우선순위) 그 부모-자식 맵을 재귀로 편다. 순환은 `breakParentCycles`가 닫는 엣지를 끊고 `capParentDepth`가 `maxCATreeDepth`(=2×maxChainDepth=16)를 넘는 사슬을 자른다 — 끊긴 노드는 최상위로 올라올 뿐 유실되지 않는다. 노드 필드: depth·leaf_count(직접 발급)·subtree_leaf_count(모든 하위 재귀 합)·leaf_preview(직접 발급 리프 만료 임박순 최대 `caLeafPreviewLimit`=5건, `listCALeafPreviews`의 row_number() 단일 쿼리)·children. 미보유 루트는 stored=false placeholder. **전체 리프는 트리에 싣지 않는다** — 노드 id를 목록 API `issued_by=`에 넣어 페이지네이션으로 받는다(같은 술어 `issuedByMatchSQL` 공유라 leaf_count와 건수 일치). 술어 우변 인덱스는 0008(subject_key_id)+0021(authority_key_id 부분·issuer_dn)) + `certificates_impact.go`("이 CA가 만료되면 영향받는 것" — `issuedByMatchSQL`을 **재귀 CTE로 전이 확장**(`certFamilySQL`/`certFamilyCTEs`, $1=대상 id, 순환은 경로 배열+`maxChainDepth` 2중 차단, 자기 자신 제외). 영향 집합 = 자신+전이 자손이고 리프·도메인·서버·만료 분포는 거기서 replaced를 뺀다(`descendant_ca_count`만 replaced 포함 — CA 트리 규약). ## 포트
- backend: 8080 / 센서 게이트웨이: 8443(`SENSOR_CA_ENC_KEY` 설정 시에만 리슨, compose도 노출) / PostgreSQL: 5432(**기본 미노출** — 여는 건 오버레이 `docker-compose.db-expose.yml`) / frontend: 3000 / (HTTPS 오버레이 사용 시) proxy: 443·80
- **포트는 전부 변경 가능**하다: 호스트측 `FRONTEND_PORT`/`BACKEND_PORT`/`SENSOR_GATEWAY_PORT`(+HTTPS 오버레이의 `HTTPS_PORT`/`HTTP_REDIRECT_PORT`, DB 오버레이의 `DB_PORT`/`DB_BIND_ADDR`), 컨테이너측 `BACKEND_INTERNAL_PORT`(바꾸면 frontend 재빌드 — `BACKEND_INTERNAL_URL`이 빌드 시 고정)·`SENSOR_GATEWAY_INTERNAL_PORT`(compose가 `SENSOR_LISTEN_ADDR`을 여기서 파생 — .env의 `SENSOR_LISTEN_ADDR`은 compose 경로에서 안 읽는다). 절차·동반 수정 표는 INSTALL 5.5
- 센서 접속 포트는 **SAN에도 센서 상태 디렉토리에도 박히지 않아 포트 변경에 재등록이 필요 없다**(`--server` 포트만 고쳐 재시작). 반면 주소(DNS/IP)는 SAN이라 `SENSOR_ADVERTISED_HOSTS` 수정 + backend 재기동이 필요하다 — 이 변수에 포트를 붙이면 기동 시 경고 후 그 항목이 무시된다

## 실행
- `cp .env.example .env && docker compose up --build` [unix] — **개발 환경 전용이다.** 폐쇄망 고객사는 Go 모듈·npm 다운로드가 막혀 소스 빌드가 성립하지 않는다: 설치도 업그레이드도 오프라인 패키지 + `install.sh`이고 절차 정본은 INSTALL 5.1.4다(OPERATIONS 5장은 백업·확인·롤백만 적고 절차는 링크한다)
- HTTPS로 띄우려면 `deploy/tls/{server.crt,server.key}`를 먼저 두고 `docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build` [unix] — 이후 모든 compose 명령에 두 파일을 함께 넘긴다(`COMPOSE_FILE` 환경변수 권장). 절차는 docs/manual/TLS.md
- `COMPOSE_PROJECT_NAME`을 `.env`에 고정하지 않으면 **업그레이드 시 빈 DB로 뜬다** — 패키지 루트=설치 루트라 신버전이 새 디렉터리에 깔리는데 compose 프로젝트명 기본값이 디렉터리명이고 `pgdata` 볼륨 이름이 거기서 나온다. `install.sh`가 이 값을 써 넣는다(절차는 INSTALL 5.1.4).
- `.env` **필수는 POSTGRES_PASSWORD 하나뿐**이다 — 관리자 계정은 첫 접속 시 `/setup` 화면에서 만든다. `BOOTSTRAP_ADMIN_USERNAME`/`_PASSWORD`는 무인 설치용 선택값(넣으면 기동 시 1회 생성, 그러면 `/setup`이 처음부터 닫혀 있다). SENSOR_CA_ENC_KEY/SENSOR_ADVERTISED_HOSTS와 포트 변수군은 compose엔 배선돼 있으나 .env.example엔 없어 수동 추가(INSTALL 5.2·5.5). 앞의 두 개는 세트 — CA 키만 넣고 HOSTS를 비우면 SAN이 없어 게이트웨이가 경고 로그 후 비활성화된다(8080은 정상 기동, 센서만 못 붙음).
- 알림·스윕·접근제한·재스캔 변수(`NOTIFY_*`/`SMTP_*`/`WEBHOOK_*`/`SYSLOG_*`/`SCAN_SWEEP_*`/`ADMIN_IP_*`/`RESCAN_*`)도 compose 패스스루만 있고 `.env.example`엔 없다 — 전부 비어도 정상(알림은 inbox만 활성, 스윕·재스캔은 기본값, 접근 제한은 허용 목록이 비어 제한 없음). 목록·기본값은 INSTALL 5.2.1·5.2.2·5.2.3·5.2.4.
- **접근 IP 제한을 브라우저 IP 기준으로 걸려면 `ADMIN_IP_TRUSTED_PROXIES`가 사실상 필수다** — 브라우저→frontend→backend 중계 구조라 backend가 보는 출발지는 frontend 컨테이너다. compose 네트워크 대역은 `docker network inspect inherit_autocert_default --format '{{range .IPAM.Config}}{{.Subnet}}{{end}}'`로 확인한다.

- 릴리즈 패키지: `sh scripts/bundle-offline.sh` (루트에서, Docker 필요) → `dist/main_<버전>.tar.gz` · `dist/sensor_linux_<버전>.tar.gz` · `dist/sensor_windows_<버전>.zip` 각각 `.sha256` 동반(+ `--target all`이면 `dist/SHA256SUMS-<버전>`). 일부만 만들려면 `--target main|sensor-linux|sensor-windows`. 고객사 측은 tar를 풀고 그 안에서 `bash install.sh` 하나만 실행한다(체크섬 대조 → load-offline 호출 → 소스 전개 → .env 생성 → 기동을 install.sh가 다 한다). 복붙용 3줄은 docs/manual/INSTALL.md 0.1, 손으로 하는 절차는 5.1, 업그레이드는 5.1.4(`COMPOSE_PROJECT_NAME` 고정 필수). 센서는 SENSOR.md 0.3 — `sudo bash install-sensor.sh` [unix] / `powershell -ExecutionPolicy Bypass -File .\install-sensor.ps1` [win]

- frontend: `npm run build`, `npm run lint`, `npm test` (frontend/ 에서). `npm test`는 Node 내장 러너(`node --test lib/*.test.mts`)로 순수 로직만 검증한다 — 추가 의존성·렌더 테스트 없음. `.mts` 테스트가 `./format.ts`를 확장자까지 적어 import하므로 tsconfig에 `allowImportingTsExtensions`가 필요하다
